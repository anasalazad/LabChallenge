## Known gotchas
- **Never run TensorFlow training and PyTorch training in the same Python process/kernel** – it segfaulted in the cloud (OpenMP/threading clash). That's why the PyTorch work is in its own notebook and the install check uses subprocesses.
- Set `TF_CPP_MIN_LOG_LEVEL=2` when executing notebooks to keep TensorFlow's C++ log spam out of the saved outputs.
- TensorFlow on native Windows is CPU-only for TF ≥ 2.11 – that's fine for this unit.
- TensorFlow may not support the very newest Python yet; Python 3.10–3.12 is the safe choice.
